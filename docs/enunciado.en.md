# Final project brief (bootcamp)

> English version of [`enunciado.md`](enunciado.md), translated for reference.
> The Spanish original is the authoritative copy: any scope decision is checked
> against it, and it is what governs the grade.

## Project goal

Build a functional, well-documented and well-presented web application that meets
the technical and methodological requirements established and learned during
the bootcamp. This project simulates a professional environment, so both the
final product and the development process will be assessed.

## Minimum requirements

- Functional minimum viable product (MVP)
- Oral presentation of the process (max. 15 minutes)
- Figma design (Sketch, Mockup, Prototype)
- Project management in JIRA (timeline, backlog, sprints)
- Technical diagrams (database and classes)
- Well-structured README file (see provided examples)
- Frontend in Vue, responsive (Mobile and Desktop)
- Backend in Java with Spring using: Spring Boot and Spring Security
- Dockerized database (MySQL or PostgreSQL)
- REST API with user login and registration

## Deliverables

- Public link to the Frontend repository
- Public link to the Backend repository
- Public link to the delivered presentation (may live in the README)

## Grading criteria

| Criterion | Points |
|---|---|
| Fully functional MVP (no serious errors) | 10 |
| Process presentation (clear workflow) | 10 |
| Figma design (sketches, mockups and prototype) | 5 |
| JIRA management (tasks and timing) | 10 |
| Technical diagrams (draw.io or Mermaid) | 10 |
| Structured README (installation, usage, etc.) | 10 |
| Vue frontend (components, hooks, component tests, responsive) | 20 |
| Spring backend (security, REST API, external DB with Docker, unit and integration tests) | 25 |

## Additional requirements (communicated outside the written brief)

- **Minimum test coverage: 70%** (our internal standard: 80% on the backend,
  70%+ on the frontend — always above the minimum).
- **E2E (end-to-end) tests** for critical user flows.

## Advice during development

- Version your code with Git and upload your project to GitHub
- Document everything you do, including technical decisions
- Test before delivering: functional, integration, etc.

## Advice for the presentation

- Prepare one slide per development stage
- First what the product is, then a visual demo, finally the process
- Explain what you did, how you did it and why
- Rehearse so you do not exceed 15 minutes
